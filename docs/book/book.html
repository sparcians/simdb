About This Book

SimDB is a high-performance, header-only C++17 module that unifies concurrent data pipelines with SQLite to power scalable simulation data engines, analysis tooling, and UI backends.

This book is written for a specific reader: the domain expert — a hardware architect, performance modeler, or researcher — who needs to move large volumes of simulation data safely and quickly, but who does not write software for a living. SimDB’s guiding principle is that it should be easy to use and hard to misuse. This book follows that same principle.

We build understanding in layers:

  • Part I explains why SimDB exists and how it differs from the alternatives.

  • Parts II—​III get you productive with the standalone SQLite interface.

  • Parts IV—​VI introduce the concurrent pipeline and app frameworks.

  • Part VII is an end-to-end case study of Argos, SimDB’s flagship collection-and-visualization application.

  • Parts VIII—​IX collect patterns, recipes, and reference material.

This is a first-draft outline. Each chapter below is scaffolded with its learning objectives, key topics, and the existing sources/snippets to draw from. Prose and worked examples are filled in during later iterations.

3. The Landscape

Position SimDB honestly against the tools a reader may already reach for.

Objectives

  • Compare SimDB with dataflow/parallel libraries and with C++ SQLite wrappers.

  • Make the differentiator concrete: no competitor unifies a safe concurrent pipeline with first-class SQLite.

  • Give clear guidance on when not to use SimDB.

Key topics

  • Dataflow / parallel libraries: Intel TBB (flow graph, concurrent containers), RaftLib (stream kernels), Folly (MPMCQueue, futures), HPX, CAF (actors) — strong concurrency, no persistence story.

  • C++ SQLite wrappers: SQLiteCpp, SOCI, sqlite_orm, sqlpp11 — SQL access, no concurrency model; locking/contention left to the user.

  • SimDB’s gap-fill: single DB thread, batched implicit transactions, retry-on-fail, approachable API.

  • Decision guide: when a plain library or an external service (e.g. Kafka, a client/server RDBMS) is the better fit.

Sources & reusable snippets

  • notes.txt — competitor notes (TBB, Folly, RaftLib) and the SQLite
    Concurrency + Flexibility differentiator.
